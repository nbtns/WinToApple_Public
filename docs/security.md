# セキュリティ設計

## Web QR受信

- セッションごとに暗号学的乱数から256 bitトークンを生成
- トークンはQR URLにだけ含め、ログや履歴へ記録しない
- URLは30分で失効
- 最初に正しいURLを開いた送信元IPへセッションを固定
- サーバーは選択した1つのIPv4アドレスで待受。家庭内LAN以外のアドレスを自動的に拒否する保証はないため、信頼できる家庭内LANでのみ使用
- ファイルIDは内部連番だけを受け付け、任意パスをURLから指定できない
- `Content-Security-Policy`、`no-store`、`no-referrer`、`nosniff`を返す
- ページ表示時にはダウンロードせず、利用者が選んだエンドポイントだけを送信
- フォルダーの一時ZIPはセッション終了後に削除
- HTTP Range以外の任意ファイルアクセスを許可しない

## 通信保護の範囲

Web版は、証明書をiPhoneへインストールせずSafariで簡単に開くため、家庭内LAN上のHTTPを使用します。QRトークンによるアクセス制御はありますが、通信は暗号化されません。同じ通信経路を観測できる相手に対する機密性は提供しません。信頼できる自宅Wi-Fi専用とし、ゲストWi-Fi、公衆Wi-Fi、共有ネットワークでは使用しません。

iPhoneアプリ版LBP2には暗号化と端末相互認証の実験実装があります。標準Web方式とは別の開発経路であり、公開版では完成済みの代替モードとして推奨していません。位置付けは[実験用コード](experimental.md)を参照してください。

## ログと秘密情報

- ファイル本文、QR URL、QRトークンを記録しない
- ファイル名、サイズ、成功状態だけを端末内履歴へ保存
- 外部解析・テレメトリーを送らない
- 証明書・秘密鍵・`.env`・ビルド済みパッケージ・診断ログをGit対象外にする
- 診断情報には端末名や個人フォルダーのパスが含まれる場合があるため、公開リポジトリへ登録しない

## 自動検査

- Semgrep: ソースコードの危険な実装を検査
- Gitleaks: APIキーや秘密情報の誤登録を検査
